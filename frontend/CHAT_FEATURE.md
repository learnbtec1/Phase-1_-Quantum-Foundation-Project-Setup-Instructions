# ميزة المحادثة الذكية مع المعلم الافتراضي (فورينا)

## نظرة عامة

تم تحويل صفحة **`/evaluate`** إلى **معلم افتراضي تفاعلي** يعتمد على شخصية **فورينا** (نموذج VRM في `public/models/Furina.vrm`). الصفحة لم تعد تعرض واجهة التقييم (الواجب وإجابة الطالب ونتائج المعايير)، بل واجهة **محادثة فقط**: إدخال نصي أو صوتي، إرسال إلى المعلم، وعرض الرد مع نطقه.

## كيف تعمل المحادثة

1. **المستخدم يكتب سؤاله** في مربع النص، أو **يسجّل صوتياً** عبر زر الميكروفون (Web Speech API).
2. عند الضغط على **إرسال**، تُرسل الرسالة من الواجهة إلى **جسر Next.js** `POST /api/chat` بصيغة `{ "message": "..." }`.
3. الجسر يوجّه الطلب إلى **الباكند** `POST /api/v1/chat` (أو ما يعادله حسب إعدادك)، حيث يُستدعى **GPT-4o** بدور معلم (فورينا) باستخدام **OPENAI_API_KEY** من `backend/.env`.
4. الباكند يعيد `{ "reply": "..." }`.
5. الواجهة تعرض الرد في فقاعة محادثة وتنطقه عبر **Web Speech API** (TTS) بالعربية إن وُجد صوت عربي في المتصفح.

## نقاط النهاية

### الباكند (FastAPI)

| المسار | الطريقة | الجسم | الاستجابة |
|--------|---------|--------|------------|
| `/api/v1/chat` | POST | `{ "message": "نص الرسالة" }` | `{ "reply": "نص الرد" }` |

- معالجة الأخطاء: في حال فشل الطلب أو غياب المفتاح، يُعاد رد مناسب أو رمز خطأ (مثلاً 400/500).
- المفتاح المستخدم: `OPENAI_API_KEY` في `backend/.env`.

### الواجهة (Next.js)

| المسار | الطريقة | الجسم | الاستجابة |
|--------|---------|--------|------------|
| `/api/chat` | POST | `{ "message": "..." }` | `{ "reply": "..." }` |

- يجري التوجيه إلى الباكند دون كشف المفتاح في المتصفح.

## الملفات ذات الصلة

| الملف | الوظيفة |
|-------|---------|
| `backend/app/api/v1/endpoints/chat.py` | نقطة نهاية المحادثة البسيطة: قبول `message` وإرجاع `reply` عبر GPT-4o. |
| `backend/app/api/v1/endpoints/tutor.py` | يحتوي على منطق الاستدعاء (مثل `_get_openai_response`) ونظام المعلم (system prompt). |
| `backend/app/main.py` | تضمين `chat_router` تحت البادئة `/api/v1`. |
| `frontend/src/app/api/chat/route.ts` | جسر يوجّه طلبات المحادثة إلى الباكند. |
| `frontend/src/app/evaluate/page.tsx` | صفحة المحادثة: أفاتار فورينا، مربع نص، ميكروفون، إرسال، فقاعات، نطق الرد. |
| `frontend/src/components/VRMAvatar.tsx` | مكون عرض شخصية VRM (فورينا). |

## الإدخال الصوتي (اختياري)

- يُستخدم **Web Speech API** (`SpeechRecognition` / `webkitSpeechRecognition`) لتحويل صوت الطالب إلى نص.
- زر الميكروفون يبدأ التسجيل، ويملأ مربع النص تلقائياً؛ الضغط مرة أخرى يوقف التسجيل.
- يعمل بشكل أفضل في متصفحات مثل Chrome و Edge، وقد يتطلب HTTPS في بيئة الإنتاج.

## المكتبات والتوافق

- **لم تُستخدم** مكتبة `@sage-rsc/talking-head-react` في التنفيذ الحالي؛ الاعتماد على مكون **VRMAvatar** (فورينا) و**Web Speech API** للنطق. إذا رغبت لاحقاً بإضافة حركة شفاه مع TTS، يمكن تثبيت المكتبة وإضافتها إلى `transpilePackages` في `next.config.js` واستخدام نموذج GLB مع المكون الناطق.
- التأكد من وجود **Furina.vrm** في `public/models/` لعرض الشخصية.

## التشغيل والاختبار

1. تشغيل الباكند (مع وجود `OPENAI_API_KEY` في `backend/.env`):
   ```bash
   cd backend && python run_server.py
   ```
2. تشغيل الواجهة:
   ```bash
   cd frontend && npm run dev
   ```
3. فتح **http://localhost:3000/evaluate**.
4. كتابة سؤال أو استخدام الميكروفون، ثم إرسال — يجب أن تظهر الشخصية ويُعرض الرد ويُنطق.

## تغيير المزاج (mood)

- تُمرَّر قيمة `mood` (مثل `neutral`, `happy`, `thinking`) إلى مكون الأفاتار حسب سياق الرد (مثلاً عند وجود كلمات إيجابية في الرد يُستخدم `happy`). يمكن توسيع المنطق لاحقاً لربط تعابير VRM فعلياً إن دعمها النموذج والمكون.
